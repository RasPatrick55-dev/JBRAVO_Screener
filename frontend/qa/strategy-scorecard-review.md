# Strategy scorecard and Backtest mapping review

## Scope and presentation

- Added the Strategy Scorecard after Metrics in the existing Screener card stack, before logs. Existing cards remain in place.
- Uses existing emerald/violet panel tokens, font families, spacing, table headers, light/dark variants and local horizontal scrolling. No global stylesheet or theme changes.
- Strategy/version attribution is visible on the Backtest and Metrics rows. Full evidence identifiers are available in expandable details without overflowing the card.
- The scorecard preserves API row order. It never ranks strategies by win rate, pools overlapping histories, or calculates an overall success rate.
- A verified ledger is labeled simulated evidence, not research qualification or trading permission. Missing actual-paper net accounting remains unavailable.

## API mapping

Backtest uses GET `/api/screener/backtest?limit=200`. There is no default `6M` query or invented window. It displays the source window/evaluation end only when provided.

Canonical Backtest fields:

| Display | Source |
| --- | --- |
| Completed sample | `closed_signals` |
| Win rate (%) | `win_rate_pct`, already percentage points |
| Net P&L (USD) | `closed_trade_net_pnl` |
| Net expectancy per completed signal (USD) | `expectancy_net_per_closed_signal` |
| Profit factor | `profit_factor` with `profit_factor_status` |
| Drawdown (USD) | `max_closed_signal_drawdown_cash`, only with `USD_CLOSED_SIGNAL_PNL` units |
| Modeled fees/slippage | `fees_closed_signals` / `slippage_closed_signals` |

Current-signal, strategy, version, report and ledger identities are retained. The unified selection definition is not attributed to individual strategy rows. Legacy return %, P/L ratio and percent-drawdown columns were removed rather than relabeled with incompatible values.

Strategy Scorecard consumes GET `/api/strategies/scorecard` with a 60-second polling interval and 35-second request deadline. Its transport evidence has a 120-second maximum age so the normal bounded refresh does not expire at the instant the one-minute poll begins; the shared hook retains its previous defaults for every other consumer. It presents only `VERIFIED` row statistics. Unknown, conflicting or unsupported evidence statuses keep financial metrics and sample sizes unknown. A current `UNAVAILABLE` response can retain validated strategy identity/reason rows without displaying performance. Generic transport-stale responses do not retain numerical rows. The explicit backend expired-cache/refresh-in-progress response is instead labeled retained evidence, preserves its original generated time, and does not claim that a successful HTTP receipt refreshed the archive. A first refresh without cached evidence displays a pending state rather than an empty sample.

The first release displays the latest completed archived snapshot for each currently configured strategy ID, not all historical version/episode groups. Each row retains its exact historical version, definition and episode, which are not proof of current deployment. Multiple archived episodes for the same configured strategy are rejected under this latest-only contract. Exact completed count, wins/losses/breakeven, net expectancy, average win/loss, payoff ratio, profit factor, modeled costs and the descriptive signal-week bootstrap interval are separately labeled. No frontend aggregation is performed. The archive date and age are separate from latest-attempt status, which is not inferred from a successful HTTP fetch. Source coverage bounds and rejected archives are visible. Evidence details also retain initial capital, allocation, position limits, fee/fill, slippage bps and evaluated/excluded/discovered coverage counts. Sparse-cluster warnings remain visible beside the descriptive interval. Response generation time, reported cache age and cache TTL are displayed separately and do not imply a new archive query or scan attempt. The backend verified-evidence cache TTL is 900 seconds.
